# Software Design and Engineering Narrative
### Artifact Description 
The artifact I have selected is an Android inventory-tracking application originally developed during my CS 360: Mobile Architecture and Programming course. Developed in Java, this application utilizes an SQLite database to allow users to add, view, and track inventory items. Additionally, it integrates device hardware permissions to send SMS notifications when new items are successfully added to the database. 
### Justification for Inclusion and Improvements 
I selected this artifact for my ePortfolio because it provided an excellent baseline for demonstrating the transition from a legacy codebase to a modern, scalable architecture. Originally, the application violated the Single Responsibility Principle by tightly coupling the UI logic, database operations, and hardware permission handling all within the DatabaseActivity class. 
To showcase my skills in software design and engineering, I improved the artifact by refactoring the application to strictly follow the MVVM (Model-View-ViewModel) architectural pattern. I created a ViewModel to manage the UI state and a Repository class to handle the SQLite database operations, which left the DatabaseActivity responsible only for observing data changes and rendering the user interface. Furthermore, I implemented strict Regular Expression (Regex) input validation on the user input fields. This specific component showcases my "security by design" mindset by actively sanitizing user input to prevent potential SQL injection attacks before the data ever reaches the database layer. 


### Course Outcome 
I successfully met the course outcomes I planned to achieve with this enhancement in Module One. By restructuring the legacy Android application to utilize the MVVM architectural pattern, I applied modern computer science practices to solve the problem of tightly coupled code. This demonstrated my ability to manage design trade-offs, as I accepted the initial overhead of creating new ViewModel and Repository classes in exchange for a significantly more scalable and maintainable software solution, successfully aligning with Course Outcome 3. Additionally, integrating strict Regex input validation demonstrated a proactive security mindset aimed at mitigating design flaws. By anticipating adversarial exploits, specifically SQL injection attacks through user input fields, this enhancement exposed and closed a critical vulnerability, ensuring the underlying SQLite database remains secure to fulfill Course Outcome 5. Because the execution of this enhancement aligned perfectly with the roadmap established during my code review, I do not have any updates or changes to my outcome-coverage plans. 
### Reflection 
Refactoring this application deepened my practical understanding of the software development lifecycle and the importance of planning before coding. As I modified the artifact, I learned how to effectively decouple an existing application without breaking its core functionality, reinforcing my ability to use architectural patterns to create highly testable and clean code. 
One of the primary challenges I faced during this process was ensuring that the legacy SMS notification system still worked seamlessly after removing the direct database logic from the UI. Because the DatabaseActivity no longer directly saved items, it did not immediately know when a save was successful. To resolve this challenge, I utilized LiveData events within the ViewModel to notify the Activity only when an item was successfully validated and inserted. This allowed the UI to trigger the SMS permission checks at the precise, appropriate time, maintaining the application's original feature set while adhering strictly to the new architectural boundaries.
