# Algorithms and Data Structures Narrative
Artifact Description 
The artifact I selected for the Algorithms and Data Structures category is a C++ Investment Portal Application, which was originally analyzed and modified during my CS 410: Reverse Software Engineering course. The application is designed to process, store, and manage investment data, allowing authenticated users to track and securely update client financial service selections (such as Brokerage or Retirement accounts). 
### Justification for Inclusion and Enhancements 
I selected this specific artifact for my ePortfolio because the original version utilized a linear search mechanism and legacy memory management practices that left it vulnerable to inefficiencies and potential memory leaks. This provided an ideal opportunity to demonstrate a clear transition from inefficient paradigms to modern, highly optimized computing solutions. 
The primary component that showcases my skills in algorithms is the complete migration of the application's search functionality to an optimized Hash Map data structure. By replacing the legacy linear global variables with a std::unordered_map, I drastically reduced the time complexity for data retrieval to an average of O(1). Furthermore, to showcase my proficiency in secure C++ coding practices, I refactored the codebase to adopt modern memory-safety techniques by replacing raw pointers with std::unique_ptr. This implementation automates memory management and natively prevents memory leaks without the need for manual garbage collection. I also encapsulated the client data into a struct to eliminate insecure global states and integrated robust security algorithms, including a three-attempt account lockout mechanism and strict std::cin.fail() input validation.

### Reflection
The process of enhancing this artifact was highly rewarding, as it allowed me to observe the tangible performance disparities between linear data structures and hash-based structures in a practical application. While creating these improvements, I significantly deepened my understanding of how critical memory ownership is in modern C++. One of the primary challenges I faced was ensuring that the transition to std::unique_ptr did not break existing data ownership scopes or cause compilation errors when passing objects between functions. I resolved this challenge by ensuring the Hash Map was passed securely by reference to functions like DisplayInfo() and ChangeCustomerChoice(). Overcoming these obstacles required precise tracking of how data moved through the system, ultimately resulting in a robust, secure, and highly efficient application.
